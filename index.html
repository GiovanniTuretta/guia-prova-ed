Módulo 0Kit de sobrevivência em C

Antes de ordenar ou buscar qualquer coisa, você precisa conseguir ler um programa em C. Aqui está só o mínimo, sem enrolação.

Programa = receita de bolo

Explicando pro macacoO computador é um cozinheiro obediente e burro. Ele segue a receita linha por linha, de cima para baixo, sem pular nada e sem adivinhar. Se a receita manda "coloque 3 ovos", ele coloca 3 ovos. Se você esqueceu de escrever "ligue o forno", o bolo não assa.

Contas que pegam iniciante

  • 7 / 2 dá 3, não 3.5. Inteiro dividido por inteiro corta a parte quebrada. Para ter 3.5: (double) 7 / 2.
  • 7 % 2 dá 1: é o resto da divisão. 137 % 10 = 7 (o último dígito). Isso é a base da tabela hash e do rand() % 100.

  • && = E (as duas coisas verdadeiras). || = OU (pelo menos uma). ! = NÃO.
  • i++ soma 1 em i. i-- tira 1. soma += x é o mesmo que soma = soma + x.

Decidir: if / else

Repetir: for e while

Explicando pro macacoO for é o treinador na pista: "comece na volta 0; enquanto for menor que 5, corra; no fim de cada volta, some 1". O while é "enquanto estiver com fome, coma banana". Ele não sabe quantas vezes vai repetir, só testa a condição.

Um for dentro de outro for é um laço aninhado. Se cada um dá n voltas, o de dentro roda n × n vezes. Guarde isso: é o motivo de Bubble Sort ser lento (Módulo 1).

Vetor = fileira de armários numerados

Explicando pro macacoVetor é um corredor de armários de escola, todos iguais, grudados um no outro. Cada armário tem um número pintado na porta. O primeiro é o 0, não o 1. Num corredor com 4 armários, os números vão de 0 a 3.
Pegadinha clássicav[4] num vetor de 4 posições não existe. O último é v[n-1]. C não avisa: lê lixo ou derruba o programa. Por isso o laço é i < n e não i <= n.

Função = máquina com entrada e saída

Explicando pro macacoUma função é um liquidificador: você põe coisas (parâmetros), ele faz o serviço e devolve um resultado (return). void é uma máquina que faz algo mas não devolve nada, tipo uma impressora.

Quando você passa um int para uma função, ela recebe uma fotocópia. Mudar a cópia não muda o original. Vetores são diferentes: a função mexe no vetor original. O Módulo 4 explica o porquê.

Módulo 1Big O: medir o esforço de um algoritmo

Explicando pro macacoVocê perdeu uma banana numa fileira de caixas. Se abrir uma caixa por vez, com 10 caixas abre até 10; com 1000 caixas abre até 1000. O trabalho cresce junto com a quantidade: isso é O(n). Big O não mede segundos. Mede como o trabalho cresce quando a entrada cresce.

Melhor, médio e pior caso

O mesmo algoritmo pode trabalhar mais ou menos dependendo de como os dados chegam. Procurar a banana na primeira caixa é o melhor caso (1 passo). Ela estar na última, ou não existir, é o pior caso (n passos). Quando a prova fala só "a complexidade de X", normalmente quer o pior caso.

Três palavras que caem em prova

  • Estável: se dois elementos têm a mesma chave, continuam na mesma ordem em que chegaram. Ex.: dois alunos com nota 8, Ana antes de Bia; um algoritmo estável mantém Ana antes de Bia.
  • In-place (no lugar): ordena dentro do próprio vetor, sem criar outro vetor do tamanho n. Merge Sort não é in-place: precisa de um vetor auxiliar.
  • Comparação × troca: comparar é perguntar "este é maior que aquele?". Trocar é mudar dois de lugar. São contadores diferentes na questão 1.

Módulo 2Ordenações simples: Bubble, Selection e Insertion

Ordenar = deixar em ordem crescente: v[0] ≤ v[1] ≤ … ≤ v[n-1]. Os três algoritmos daqui são fáceis de escrever e lentos para muitos dados (O(n²)). Vamos usar sempre o mesmo vetor [7, 3, 5, 2] para comparar.

Bubble Sort: as bolhas sobem

Explicando pro macacoMacacos em fila, do mais baixo ao mais alto. Você anda pela fila olhando só dois vizinhos por vez. Se o da esquerda for mais alto, troca os dois de lugar. No fim da primeira passada, o mais alto de todos foi "empurrado" até o final, igual bolha subindo na água. Repete a passada, agora ignorando o último (já está certo).

No exemplo: 6 comparações e 5 trocas. Melhor caso (já ordenado): uma passada sem trocas e para, O(n). Pior caso (ordem decrescente): O(n²). É estável.

Selection Sort: escolher o menor

Explicando pro macacoEducação física, escolhendo time. Você olha todo mundo que sobrou, aponta o mais baixinho e coloca ele na primeira posição livre. Depois olha de novo o resto, aponta o próximo mais baixinho, e assim vai. Muitas olhadas (comparações), poucas trocas: no máximo uma por rodada.

No exemplo: 6 comparações e só 1 troca. Faz sempre n(n−1)/2 comparações, esteja o vetor ordenado ou não: O(n²) no melhor, médio e pior caso. Não é estável (a troca "de longe" pode passar um igual na frente do outro).

Insertion Sort: arrumar cartas na mão

Explicando pro macacoVocê recebe cartas de baralho uma por vez. A mão já está arrumada. Pega a carta nova, e vai empurrando para a direita as cartas maiores que ela, até achar o buraco certo. Encaixa. Pega a próxima.

No exemplo: 6 comparações e 5 movimentações. Melhor caso (já ordenado): O(n), só uma comparação por carta. Pior caso: O(n²). É estável e é o melhor dos três quando o vetor já está quase ordenado.

A forma "compacta" que aparece em livros (e nas aulas) junta as duas condições: while (j >= 0 && v[j] > chave). A ordem importa: primeiro testa j >= 0, senão acessaria v[-1].

Módulo 3Recursão, Quick Sort e Merge Sort

Recursão: uma função que chama ela mesma

Explicando pro macacoFila do cinema, escuro. Você quer saber em que posição está. Pergunta pra quem está na frente: "qual a sua posição?". Ele pergunta pro da frente dele, que pergunta pro da frente… até chegar no primeiro, que sabe a resposta sem perguntar: "sou o 1". Esse é o caso base. A resposta volta passando de mão em mão, cada um somando 1.
Sem caso base = explodeSe a função nunca para de se chamar, a memória de chamadas (a "pilha") enche e o programa trava com stack overflow. Toda recursão precisa de: 1) caso base, 2) chamada com um problema menor.

Quick Sort: escolher um pivô e separar

Explicando pro macacoO professor escolhe um macaco da fila: o pivô (aqui, sempre o último). Todo mundo menor ou igual a ele vai para a esquerda, todo mundo maior vai para a direita, e o pivô fica no meio. Pronto: o pivô já está no lugar definitivo. Agora faz a mesma coisa só com o grupo da esquerda, e depois só com o grupo da direita. Grupos de 0 ou 1 macaco já estão ordenados.

Rastreamento do particionamento (Lomuto) em [7, 3, 5, 2, 6, 4], pivô = 4:

Agora ordena [3, 2] e [7, 6, 5] do mesmo jeito. O 4 nunca mais se mexe.

Custo: se o pivô cai perto do meio, são log n níveis com n comparações cada: O(n log n). Se o pivô for sempre o maior ou o menor (vetor já ordenado, com pivô no último), um lado fica vazio e vira O(n²). Não usa vetor auxiliar, mas a recursão gasta memória de pilha. Não é estável.

Merge Sort: dividir e intercalar

Explicando pro macacoUm baralho bagunçado. Você divide ao meio e entrega para dois amigos. Eles dividem de novo, e de novo, até cada um ter uma carta só (uma carta sozinha já está ordenada). Agora, na volta, cada dupla junta suas duas pilhas: olha a carta de cima de cada pilha, pega a menor, repete. Juntar duas pilhas já ordenadas é fácil e rápido.

Intercalando [3, 7] com [2, 5]: compara 3 e 2, pega 2. Compara 3 e 5, pega 3. Compara 7 e 5, pega 5. Sobrou 7, copia. Resultado [2, 3, 5, 7].

Custo: O(n log n) sempre (melhor, médio e pior), porque divide sempre ao meio, não importa os valores. Preço: precisa de um vetor auxiliar de tamanho n, O(n) de memória extra. É estável.

Módulo 4Ponteiros e memória dinâmica

Endereço: o número da casa

Explicando pro macacoA memória do computador é uma rua gigante de casinhas, todas numeradas. Cada variável mora numa casa. O número da casa é o endereço. Um ponteiro é um papelzinho onde está anotado o endereço de outra casa. Com o papelzinho na mão você pode ir até lá e mexer no que tem dentro, mesmo sem saber o nome de quem mora.

Acima: x mora na casa 1000 e guarda 10. p mora na casa 2000 e guarda o número 1000, ou seja, "aponta para" x.

Agora faz sentido o & do scanfscanf("%d", &idade) entrega para o scanf o endereço de idade. Sem isso, o scanf não saberia em qual casa guardar o número digitado.

Por que a função trocar precisa de ponteiros

Passar uma variável comum para uma função entrega uma fotocópia. A função troca as cópias, e os originais ficam iguais. Passando os endereços, a função vai até as casas originais.

Esse é também o jeito de uma função "devolver" mais de um resultado: void maior_menor(int *v, int n, int *maior, int *menor) escreve nos dois endereços recebidos.

Vetor e ponteiro são quase a mesma coisa

O nome do vetor é o endereço do primeiro armário. Por isso, ao passar um vetor para uma função, ela mexe no original. E dá para andar pelos armários com aritmética de ponteiro:

malloc: pedir memória durante a execução

Explicando pro macacoint v[100] é comprar um terreno de tamanho fixo antes de saber quantos parentes vêm na festa. malloc é ligar para a prefeitura na hora da festa: "chegaram N pessoas, me dá um terreno para N". A prefeitura devolve o endereço do terreno (ou NULL se não tiver espaço). Quando a festa acaba, você devolve o terreno com free. realloc é pedir para aumentar ou diminuir o terreno, levando a mobília junto.

Por que a binária exige vetor ordenado (a lista pede para demonstrar)

Módulo 6Tabela hash

Explicando pro macacoUm guarda-volumes com 10 escaninhos, numerados de 0 a 9. A regra da casa: "seu escaninho é o último dígito do seu código". Código 137 vai no escaninho 7. Para achar o 137 depois, ninguém procura em todos: vai direto no 7. Essa regra é a função hash. Achar algo vira quase 1 passo, não importa quantos itens existam.

Função hash

Uma boa função hash é rápida e espalha as chaves pelas posições. Usar tamanho primo (ex.: 11, 13) costuma espalhar melhor que 10.

Colisão: dois na mesma gaveta

101 e 111 dão resto 1. Os dois querem o escaninho 1. Isso é uma colisão, e ela é inevitável quando há mais códigos possíveis do que gavetas. A lista exige que você trate colisões com uma de duas estratégias:

Estratégia 1: encadeamento (lista em cada gaveta)

Explicando pro macacoCada escaninho tem um gancho. Chegou alguém novo para uma gaveta ocupada? Pendura no gancho, formando uma corrente. Cada elo da corrente sabe quem é o próximo. O último aponta para "ninguém" (NULL).
[0]NULL
[1]121 Café→111 Açúcar→101 Arroz→ NULL
[5]205 Feijão→ NULL
[7]37 Leite→ NULL

Essa corrente é uma lista encadeada: cada nó é uma struct que carrega os dados e um ponteiro para o próximo nó.

Para percorrer uma gaveta: comece em tabela[g] e siga atual = atual->proximo até chegar em NULL. Para remover um nó do meio, faça o anterior "pular" o removido: anterior->proximo = atual->proximo, depois free(atual).

Estratégia 2: endereçamento aberto (sondagem linear)

Explicando pro macacoEstacionamento. Sua vaga é a 1, mas tem carro nela? Tenta a 2. Ocupada? Tenta a 3. Estaciona na primeira livre. Para achar seu carro depois, faz o mesmo caminho: começa na 1 e anda até achar ou até topar com uma vaga que nunca foi usada.
[1]101vaga dele
[2]111queria a 1, andou 1 passo
[3]121queria a 1, andou 2 passos

Tudo fica no próprio vetor, sem ponteiros. Detalhe que cai: ao remover, marque a vaga como "removida" em vez de esvaziar. Se esvaziar a vaga 2, a busca pelo 121 pararia nela achando que ele não existe.

O fator de carga α = elementos ÷ gavetas diz o tamanho médio de cada corrente. Com 5 produtos em 10 gavetas, α = 0,5. Quanto menor α, mais perto de O(1).

Resposta pronta para "explique a diferença de custo"Na busca sequencial, o programa compara a chave com cada registro até encontrá-lo; com n registros, são até n comparações, custo O(n). Na tabela hash, a função hash calcula diretamente a posição da chave, então a busca examina apenas os poucos elementos daquela posição. Com uma boa função hash e fator de carga baixo, o custo médio é O(1), independente de n. O pior caso da hash é O(n), quando todas as chaves colidem na mesma posição.

Módulo 7Bônus: os outros quatro da apostila

A lista não pede, mas a apostila do professor traz. Se sobrar tempo, saiba pelo menos a ideia e o Big O de cada um.

  • Shell Sort: Insertion Sort com "saltos". Primeiro ordena elementos distantes (intervalo n/2, depois n/4…) e termina com intervalo 1, que é um Insertion normal. Pior caso O(n²) com intervalos pela metade. Não é estável.
  • Heap Sort: monta um heap máximo (árvore guardada no vetor em que todo pai ≥ filhos; filhos de i ficam em 2i+1 e 2i+2). Tira o maior da raiz, joga no fim, conserta o heap, repete. O(n log n) no pior caso e memória O(1). Não é estável.
  • Counting Sort: não compara. Conta quantas vezes cada valor aparece (vetor de contagens de 0 até k−1) e usa as somas acumuladas para posicionar. O(n + k). Só serve para inteiros num intervalo pequeno. Estável.
  • Radix Sort: ordena dígito por dígito, das unidades para as centenas, usando uma ordenação estável (Counting) em cada passada. O(d·(n + b)), com d dígitos e base b. Estável.

Módulo 8Na hora da prova

Esqueleto para começar qualquer questão

Checklist antes de entregar

  • Todo malloc tem um teste de NULL e um free no fim.
  • Laços vão de 0 até < n. Nada de v[n].
  • Cada algoritmo de ordenação roda numa cópia do vetor original. Contadores zerados antes de cada um.
  • Quick e Merge: chamada inicial com 0 e n - 1. Caso base inicio < fim.
  • Busca binária: vetor ordenado antes. meio = inicio + (fim - inicio) / 2. Laço while (inicio <= fim).
  • Strings: strcpy para copiar, strcmp para comparar. Nada de = ou == em texto.
  • Struct por ponteiro usa ->; struct direta usa ..
  • Hash: tratar código negativo; remover com o ponteiro anterior; liberar cada nó.

Perguntas teóricas prováveis, com resposta curta

PerguntaResposta em uma frase
Por que a busca binária exige ordenação?Porque ela descarta metade do vetor comparando com o meio, e isso só é correto se tudo à esquerda for menor e tudo à direita for maior.
Qual ordenação foi melhor nos testes?Quick e Merge, com muito menos comparações, porque são O(n log n) contra O(n²) dos simples; a diferença cresce com N.
Quando o Quick Sort fica O(n²)?Quando o pivô é sempre o menor ou o maior elemento, por exemplo com vetor já ordenado e pivô no último.
Por que o Merge usa mais memória?Porque intercala as metades num vetor auxiliar de tamanho n.
O que é colisão?Duas chaves diferentes que a função hash manda para a mesma posição.
O que acontece sem free?Vazamento de memória: o bloco fica reservado até o programa acabar.
Diferença entre *p e &x?&x pega o endereço de x; *p acessa o valor guardado no endereço que p contém.
Algoritmo estável?Mantém a ordem original entre elementos de chave igual. Bubble, Insertion e Merge são; Selection e Quick não.

Resumão

Uma página para reler antes de entrar na sala.

C básico

v[0] é o primeiro; v[n-1] o último. 7/2 = 3; 7%2 = 1. = guarda, == compara. Texto: strcpy, strcmp(a,b)==0.

Big O

O(1) acesso direto e hash média · O(log n) busca binária · O(n) sequencial · O(n log n) Merge, Quick médio · O(n²) Bubble, Selection, Insertion, Quick pior. N×10: n² faz ×100; n log n faz ≈ ×13.

Bubble

Troca vizinhos; maior vai para o fim. Parada antecipada se não trocou. Melhor O(n), pior O(n²). Estável.

Selection

Acha o menor do resto, troca com a posição i. Sempre n(n−1)/2 comparações, O(n²). Até n−1 trocas. Não estável.

Insertion

Guarda chave = v[i], empurra maiores para a direita, encaixa em v[j+1]. Melhor O(n), pior O(n²). Estável.

Quick

Pivô = último. i = inicio-1; se v[j] <= pivo: i++, troca. No fim troca v[i+1] com v[fim]. Recursão em (inicio, p-1) e (p+1, fim). O(n log n) médio, O(n²) pior. Não estável.

Merge

meio = inicio + (fim-inicio)/2; ordena metades; intercala com <= num auxiliar. O(n log n) sempre, O(n) memória. Estável.

Ponteiros

&x endereço · *p conteúdo · v[i] == *(v+i) · p->campo == (*p).campo. Função que altera a variável de fora recebe o endereço.

Memória

int *v = malloc(n * sizeof(int)); if (v == NULL) … · novo = realloc(v, k * sizeof(int)); if (novo) v = novo; · free(v); v = NULL; · malloc tem lixo, calloc zera.

Buscas

Sequencial: qualquer ordem, O(n). Binária: só ordenado, while (inicio <= fim), descarta metade, O(log n). 1000 itens: 10 olhadas.

Hash

h = cod % TAM; if (h < 0) h += TAM; Colisão = chaves diferentes, mesma posição. Encadeamento: lista por gaveta (proximo, NULL). Aberto: tenta (h+t) % TAM; remoção marca "removido". Busca O(1) médio, O(n) pior. α = n / TAM.

Frases prontas

Binária exige ordem porque decide o lado comparando com o meio. Quick/Merge venceram por serem O(n log n). Hash calcula a posição em vez de percorrer tudo.
